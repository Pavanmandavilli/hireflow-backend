# my-service

Production-ready FastAPI microservice generated by **create-fastapi-service**.

## Enabled Features

- **POSTGRES**: PostgreSQL + async SQLAlchemy
- **REDIS**: Redis cache + @cache() decorator
- **JWT**: JWT RS256 authentication
- **DOCKER**: Dockerfile + docker-compose.yml
- **WORKERS**: Async background worker

## Quick Start

```bash
# Create and activate virtual environment
uv venv && source .venv/bin/activate

# Install dependencies
uv sync

# Copy and adjust environment variables
cp .env .env.local

# Run development server
uvicorn app.main:app --reload

# Run production server
gunicorn -c gunicorn.conf.py app.main:app
```

- **postgres** — PostgreSQL on :5432
- **redis** — Redis on :6379

## Authentication

JWT RS256 keys are pre-generated in `keys/`.

Obtain a token (example):
```python
from app.auth.jwt_handler import create_access_token
token = create_access_token(subject="user@example.com")
```

Use it in requests:
```
Authorization: Bearer <token>
```

## Architecture

```
Request → Middleware → Router → Endpoint → Service → Repository → Database
```

Each layer has a single responsibility:
- **Endpoint** — HTTP schema validation, request/response mapping
- **Service** — Business logic orchestration
- **Repository** — Data access abstraction
- **Model** — Persistence schema

## Project Structure

```
app/
├── api/v1/endpoints/   # HTTP handlers
├── auth/               # JWT RS256
├── cache/              # Redis + @cache()
├── core/               # Settings (pydantic-settings)
├── db/                 # Async SQLAlchemy session
├── dependencies/       # FastAPI Depends() factories
├── kafka/              # Producer / Consumer
├── logging/            # Structured logger
├── middleware/          # Request ID, context logging
├── models/             # ORM / dataclass models
├── repositories/       # DB queries
├── schemas/            # Pydantic I/O schemas
├── services/           # Business logic
├── utils/              # OpenTelemetry tracing
└── workers/            # Async background tasks
```

## AI Hiring Assistant APIs

The service now includes the backend for the Hunar.AI take-home assignment.

Base path (with the default `APP_NAME=hiring-assistant`): `/hiring-assistant/api/v1/hiring`

| Method | Endpoint | Purpose |
|---|---|---|
| POST | `/jobs` | Create a job from a JD |
| GET | `/jobs` | List jobs |
| GET | `/jobs/{job_id}` | Get job details |
| POST | `/candidates/search` | Search people for a job (PDL or demo fallback) |
| GET | `/candidates?job_id=1` | List candidates |
| GET | `/hunar/agents` | List Hunar voice agents |
| GET | `/hunar/numbers` | List Hunar phone numbers |
| POST | `/calls` | Start one candidate outreach/interview call |
| POST | `/calls/bulk` | Start outreach for multiple candidates |
| GET | `/calls?job_id=1` | List call attempts |
| GET | `/calls/{call_id}` | Get call/result details |
| POST | `/webhooks/hunar` | Receive Hunar call lifecycle/result updates |

Hunar authentication is server-side only using `X-API-Key`. Set `HUNAR_API_KEY` in `.env`; never expose it to the React/Next.js client.

For local development, `PDL_API_KEY` can be left empty and the API returns demo candidates so the complete UI flow can be demonstrated without a People Data Labs account.
